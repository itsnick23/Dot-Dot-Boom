1. Problema y Objetivos del Proyecto Apartado 1 & 2

⚠️ El Problema del Buscaminas Clásico

  • Determinismo rígido: Un solo error fortuito destruye la partida de inmediato.
  • Adivinanzas ciegas: Situaciones 50/50 donde la deducción lógica matemática no es suficiente.
  • Falta de progresión: No existe acumulación de recursos, mejoras o rejugabilidad estratégica.

🎯 Objetivos y Propuesta de Dot-Dot-Boom

  • Fusión Roguelike: Introducir economía (monedas), vidas progresivas, tienda táctica y reliquias.
  • Garantía Matemática (BFS): Algoritmo de conectividad que asegura tableros 100% conexos y resolubles.
  • Dominio Estricto de POO: Modelar la complejidad del juego utilizando polimorfismo, encapsulamiento, composición y persistencia sin acoplar la lógica a la interfaz.

2. Funcionalidades del Videojuego Apartado 3.9

🗺️ Rondas Progresivas

10 rondas de combate. El tablero escala desde 5×5 hasta 23×23 con densidad creciente de minas.

👞 El Zapato Táctico

Herramienta consumible para inspeccionar celdas a distancia: desactiva bombas en 3×3 sin perder vida o revela zonas seguras.

🎖️ 25 Chapas (Reliquias)

4 rarezas (Común, Rara, Épica, Legendaria) que otorgan habilidades activas/pasivas modificando las reglas en runtime.

🛒 Tienda Táctica

Se activa cada 5 casillas seguras. Permite comprar suministros y vender chapas equipadas por el 50% de su valor.

💾 Persistencia Doble

Guardado/recuperación de partidas activas (partida.txt) y Salón de la Fama con récords (scores.txt).

🖥️ Doble Interfaz

Modo visual de alto rendimiento con SFML 3 (60 FPS) y modo terminal puro (prueba.cpp) para verificación técnica.

3. Arquitectura del Software Criterio 3.1

Se diseñó una arquitectura desacoplada donde el Backend (Dominio) es completamente autónomo y agnóstico a la librería gráfica:

  • Celda: Unidad atómica de información.
  • Tablero: Matriz dinámica 2D, adyacencias y grafos.
  • Chapa: Jerarquía polimórfica de habilidades.
  • Inventario: Colección de reliquias equipadas.
  • Partida: Máquina de estados, economía y persistencia.

  • test/prueba.cpp: Interfaz de consola que prueba el 100% de la lógica sin dependencias gráficas.

5. Composición, Agregación y Asociación Criterio 3.2

💎 Composición

Relación fuerte de pertenencia y ciclo de vida:

class Partida {
private:
    Tablero tablero;
    Inventario inventario;
};

Si la Partida es destruida, el tablero y el inventario se destruyen automáticamente.

📦 Agregación

Contenedor de referencias independientes:

class Inventario {
private:
    Chapa* chapas[5];
};

El inventario administra punteros a chapas que existen independientemente en el catálogo del juego.

🔗 Asociación

Interacción sin posesión:

int cargarPuntajes(
    const string& ruta, 
    RegistroPuntaje* lista
);

Partida opera sobre registros de puntuación temporales para lectura y ordenamiento.

6. Herencia y Polimorfismo Dinámico Criterio 3.4

🏛️ Clase Base Abstracta (Chapa)

Contiene el método virtual puro clonar() = 0 (Patrón Prototype) y destructor virtual:

class Chapa {
public:
    virtual ~Chapa();
    virtual Chapa* clonar() const = 0;
    virtual void alDestapar(...);
    virtual bool alPisarMina(...);
};

🌱 25 Clases Derivadas

Ejemplo: ChapaBlindaje bloquea daño, ChapaSaqueador bonifica monedas por minas vecinas, ChapaMidas multiplica ingresos.

⚡ Despacho Dinámico (Dynamic Dispatch)

En tiempo de ejecución, el motor invoca los métodos polimórficos a través de punteros a la clase base sin conocer el tipo derivado concreto:

// Despacho polimórfico al destapar
for (int i = 0; i < inventario.getCantidad(); i++) {
    inventario.getChapa(i)->alDestapar(
        dinero, zapatos, minasCerca, cascada
    );
}

✓ Permite desacoplar y extender el sistema agregando nuevas chapas sin modificar el motor central.

7. Encapsulamiento y Gestión de Recursos Criterios 3.3 & 3.5

🛡️ Encapsulamiento con Validación

Todos los estados sensibles son private o protected con setters que validan invariantes:

void Celda::setMinasCerca(int cant) {
    if (cant < 0) cant = 0;
    if (cant > 8) cant = 8;
    minasCerca = cant;
}

Protección de coordenadas inválidas y prevención de estados corruptos en el tablero.

💾 Gestión de Memoria Dinámica Justificada

El tamaño del tablero varía de ronda en ronda (5×5 a 23×23), requiriendo asignación dinámica manual:

void Tablero::liberar() {
    if (celdas != nullptr) {
        for (int i = 0; i < filas; i++)
            delete[] celdas[i];
        delete[] celdas;
        celdas = nullptr;
    }
}

✓ Sin fugas de memoria (destructores en Tablero, Inventario y Partida).

9. Algoritmos y Colecciones de Objetos Criterio 3.7

🌐 Algoritmo de Grafos / Conectividad (BFS)

En Tablero::tableroConexo, se ejecuta una Búsqueda en Anchura (BFS) con cola FIFO:

  • Garantiza que todas las celdas seguras formen un único componente conexo transitable.
  • Impacto: Elimina las partidas frustrantes de adivinanza ciega obligando a que el mapa sea deducible.

📊 Algoritmo de Ordenamiento

En Partida::cargarPuntajes, se implementa un algoritmo de ordenamiento por intercambio:

  • Ordena el vector de puntuaciones utilizando la sobrecarga RegistroPuntaje::operator<.
  • Permite que el Salón de la Fama siempre presente en tiempo real las 10 mejores marcas históricas.
